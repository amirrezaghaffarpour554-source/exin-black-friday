# راه‌اندازی Cron و Action Scheduler

صف قیمت‌گذاری با Action Scheduler همراه WooCommerce اجرا می‌شود. وجود Action Scheduler به‌تنهایی اجرای به‌موقع را تضمین نمی‌کند؛ WP-Cron معمولی به بازدید وابسته است. برای کمپین واقعی، Cron سرور با فاصلهٔ کوتاه لازم است.

## روش پیشنهادی با WP-CLI

روی سرور Staging، مسیر PHP و WordPress را با مقادیر واقعی جایگزین کنید. فرمان را با همان کاربر مالک فایل‌های سایت اجرا کنید؛ از کاربر root برای فایل‌های سایت استفاده نکنید.

```cron
* * * * * /usr/bin/php /usr/local/bin/wp --path=/var/www/example/public cron event run --due-now --quiet >> /var/log/example-wp-cron.log 2>&1
```

ابتدا فرمان را دستی اجرا و دسترسی فایل Log را بررسی کنید. اگر WP-CLI به‌صورت Phar نصب شده، مسیر آن را جایگزین کنید. اجرای موفق فرمان باید در داشبورد افزونه و فهرست Scheduled Actions ووکامرس با پیشرفت صف تأیید شود.

پس از تأیید اجرای واقعی Cron سرور، می‌توانید در `wp-config.php` بازدیدمحور بودن WP-Cron را غیرفعال کنید:

```php
define( 'DISABLE_WP_CRON', true );
```

این تغییر را بدون Cron سالم انجام ندهید؛ در غیر این صورت صف ووکامرس و سایر افزونه‌ها نیز عقب می‌افتند. فایل `wp-config.php` را افزونه خودکار تغییر نمی‌دهد.

اگر میزبان فرمان Action Scheduler CLI را نصب کرده است، `wp help action-scheduler` را بررسی کنید و Runner را مطابق مستندات همان نسخه و بدون Worker تکراری تنظیم کنید. فرمان‌های این افزونه جایگزین Runner ووکامرس نیستند.

## زمان‌ها

دادهٔ Job و شروع/پایان به UTC ذخیره می‌شوند. نمایش و مرز روز براساس منطقهٔ کمپین است. برای `Asia/Tehran` ساعت ۰۰:۰۰ روز ۲۷ نوامبر ۲۰۲۶ برابر ۲۰:۳۰ UTC روز ۲۶ نوامبر است. ساعت صحیح سیستم سرور و NTP اهمیت دارد؛ شمارش معکوس مرورگر با اختلاف ساعت سرور هماهنگ می‌شود.

Job دیررس باید قیمت روز فعلی را اعمال کند. بعد از اختلال، همهٔ مرحله‌های قدیمی به‌ترتیب اجرا نمی‌شوند. توقف/ادامه و تغییر نسخه باعث بی‌اعتبارشدن درخواست قدیمی می‌شود. قیمت‌گذاری به Batch تقسیم شده و خطای موقت با Retry محدود و فاصلهٔ افزایشی ثبت می‌شود.

## کنترل سلامت

1. در ابزار Scheduled Actions ووکامرس، گروه `exin-black-friday` و Actionهای در انتظار یا شکست‌خورده را بررسی کنید.
2. در عیب‌یابی افزونه، آخرین اجرای موفق و خطای محصول را ببینید.
3. کمپین آزمایشی کوتاه با یک محصول بسازید و رسیدن قیمت زمان جاری را بررسی کنید.
4. توقف، ادامه و Job قدیمی را تست کنید؛ قیمت بعد از توقف نباید تغییر آینده داشته باشد.
5. بازیابی پایان طبیعی و Retry یک خطای کنترل‌شده را بررسی کنید.

حذف کورکورانهٔ صف یا اجرای دستی SQL برای «رفع گیرکردن» می‌تواند نتیجهٔ بازیابی را نامشخص کند. ابتدا Log، وضعیت محصول و Snapshot را بررسی کنید. غیرفعال‌سازی افزونه قیمت را خودکار برنمی‌گرداند؛ برای توقف طولانی، فرایند بازیابی را جداگانه کامل کنید.
