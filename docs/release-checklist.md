# چک‌لیست انتشار و پذیرش Staging

این فهرست باید با شواهد محیط مقصد تکمیل شود؛ تیک‌نخورده به‌معنای تأیید نیست. انتشار Production در این مأموریت انجام نمی‌شود.

## بسته و نصب

- [ ] ZIP با نام `exin-black-friday-v1.0.0.zip` و یک ریشهٔ `exin-black-friday` ساخته شده است.
- [ ] فایل‌های تست، `work`، Vendor توسعه، Git، Log، Token و اطلاعات محرمانه در ZIP نیستند.
- [ ] Hash بسته و Commit منبع ثبت شده‌اند.
- [ ] نصب تمیز، فعال‌سازی، غیرفعال‌سازی، فعال‌سازی مجدد و ارتقا بدون Fatal تأیید شده‌اند.
- [ ] WooCommerce غیرفعال و Elementor غیرفعال باعث Fatal نمی‌شوند.
- [ ] حذف پیش‌فرض داده را حفظ می‌کند و Opt-in در حضور مالکیت باز مانع حذف مخرب می‌شود.

## قیمت و بازیابی

- [ ] محصول ساده و Variation مستقل با کف معتبر اضافه شده‌اند.
- [ ] روز اول، روز آخر، کمپین یک‌روزه، پایه برابر کف و مبالغ اعشاری تأیید شده‌اند.
- [ ] برنامهٔ خطی و تصاعدی غیرصعودی‌اند و روز آخر دقیقاً کف است.
- [ ] Sale فعال، Sale زمان‌بندی‌شده و قیمت پویا به‌صورت امن بررسی شده‌اند.
- [ ] Job تکراری و دیررس، Retry و قطع پردازش قیمت را خراب نمی‌کنند.
- [ ] توقف بدون Restore، ادامه و Job نسخهٔ قدیمی بررسی شده‌اند.
- [ ] پایان طبیعی و Restore صریح نتیجهٔ پایدار برای همهٔ محصولات دارند.
- [ ] تغییر دستی قیمت باعث بازنویسی ناخواسته نشده و Conflict قابل بررسی است.
- [ ] Snapshot و Audit در خروجی عمومی دیده نمی‌شوند.

## سفارش و ارسال

- [ ] موجودی، Backorder، Reservation و Variation Stock با رفتار ووکامرس صحیح‌اند.
- [ ] تغییر قیمت میان افزودن به سبد و Checkout در خرید واقعی تست شده است.
- [ ] خرید Classic و Blocks با درگاه آزمایشی، پرداخت موفق و بازگشت تکراری تست شده‌اند.
- [ ] سفارش ثبت‌شده با Job بعدی تغییر مبلغ نمی‌دهد.
- [ ] سفارش مختلط/چندقلمی یک بار شمرده و درآمد اقلام از کل سفارش جداست.
- [ ] Failed، Cancelled، Refund جزئی و کامل در گزارش درست لحاظ می‌شوند.
- [ ] HPOS روشن و حالت ذخیره‌سازی واقعی فروشگاه تست شده‌اند.
- [ ] ارسال در کمتر/برابر/بیشتر از حدنصاب، با کوپن، حذف کالا و تغییر تعداد تست شده است.
- [ ] فقط Flat Rate انتخاب‌شده رایگان می‌شود و چند Package مستقل درست کار می‌کنند.

## امنیت، نمایش و زیرساخت

- [ ] کاربر بدون مجوز، nonce نامعتبر، ورودی مخرب و درخواست ID دست‌کاری‌شده رد می‌شوند.
- [ ] Endpoint عمومی قادر به اجرای عملیات قیمت یا خواندن دادهٔ محرمانه نیست.
- [ ] پنج شورت‌کد و شش ویجت Elementor و پیام کمپین غیرفعال بررسی شده‌اند.
- [ ] قیمت جاری، تخفیف معتبر، تصویر و موجودی در موبایل و دسکتاپ صحیح‌اند.
- [ ] شمارش معکوس با اختلاف ساعت دستگاه مشتری صحیح است.
- [ ] Cron واقعی و مانیتور آخرین اجرا/Failed Actions برقرارند.
- [ ] Redis و کش محصول/Variation، Full Page Cache و CDN پس از تغییر قیمت بررسی شده‌اند.
- [ ] Benchmarkهای ۱۰۰ و ۱۰۰۰ محصول با محیط، حافظه، Query و زمان واقعی ثبت شده‌اند.
- [ ] Backup و روش Rollback عملیاتی و مسیر رسیدگی به Conflict تعیین شده‌اند.
- [ ] گزارش تست، محدودیت‌ها، Hash بسته و PR بازبینی شده‌اند.

پس از تأیید این موارد، تصمیم انتشار Production با مالک فروشگاه است. جایگزینی فایل افزونه Rollback قیمت نیست؛ در برنامهٔ بازگشت، نتیجهٔ Restore یا حفظ آگاهانهٔ تغییر خارجی را جدا ثبت کنید.
